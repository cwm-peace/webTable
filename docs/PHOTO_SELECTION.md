# 手机照片选择排查与修复

日期：2026-11-01。反馈为“在照片选择器中选中了图片，页面却没有加入成功”。没有设备型号、系统、浏览器、图片样本或报错，不能将某一缺陷确定为这次反馈的唯一原因。图片读取、处理和保存均发生在浏览器本机，没有上传接口。

## 已确认的问题

| 路径 | 原行为与影响 | 修复 |
| --- | --- | --- |
| PNG 容器校验 | 只允许非交错 PNG，合法 Adam7 交错图片被报为损坏 | 接受交错方法 0、1，继续拒绝非法值、CRC 错误和截断 |
| PNG 方向 | eXIf 未按 TIFF 字节序与 IFD 偏移读取，可能漏掉旋转方向，进而把解码宽高交换判断为错误 | 按 TIFF 结构读取方向，验证范围和边界 |
| 相册返回的类型 | 合法图片内容与 File.type 不一致时直接拒绝；相册或文件提供器转码后可能留下旧类型 | 已通过检查的真实内容优先，统一内存 Blob 类型，损坏图片仍拒绝 |
| 图片解码 | 存在 createImageBitmap 并不保证它能解码每种格式或正确处理方向；原路径回退不完整 | 位图解码失败或尺寸不匹配时尝试图片元素；页面回退使用普通 canvas |
| 低内存降采样 | 浏览器主动缩小解码尺寸时，原来的严格尺寸相等检查会误拒 | 接受不放大、不交换横竖方向的等比缩小及 1 像素取整误差；仍拒绝比例异常，保留原件时继续记录文件原尺寸 |
| 异步处理挂起 | Worker 不发消息、读取或编码不返回时，可能一直忙碌 | 单次读取、摘要、解码、编码有 20 秒等待上限；Worker 30 秒无进度则终止并尝试页面处理；支持取消与晚到资源释放 |
| 重复读取相册文件 | 后续解码或保存可能再次读取外部文件提供器的 File | 首次成功读取后建立内存 Blob，后续使用该快照 |
| 手机可见反馈 | 错误与进度位于页面顶部，下面的槽位看起来没有变化；照片处理没有取消入口 | 当前槽位显示进度、错误及取消按钮；失败或取消保留原图，可重新选择相同文件 |
| 预览失败 | 临时 URL 创建失败或 img 加载失败缺少局部说明 | 显示“已加入但预览无法显示”，释放 URL，隔离旧预览事件 |

选择器使用 `accept="image/*"` 提示系统选择图片。`accept` 只是选择提示，实际接收仍经过内容检查与本机解码，不根据扩展名信任文件，不依赖 User-Agent 分支。它不保证系统把 HEIC 转换成 JPEG。

## 模拟范围

自动化使用合成图片和虚构表单，通过 Chromium、Playwright WebKit 的窄屏布局与 API 故障注入检查本机处理路径。以下能力组合覆盖可能出现在不同手机上的行为，不代表对应系统已经验收：

| 目标场景 | 模拟方法 | 无法据此验证的内容 |
| --- | --- | --- |
| Android 浏览器 | Chromium、窄屏布局、错误或空 MIME、位图 API 失败、Worker 无响应 | Android 系统相册、云照片下载、厂商 WebView 与权限 |
| iOS 浏览器 | Playwright WebKit、普通图片元素/canvas 回退、文件读取失败、选择/取消重试 | 发行版 Safari、系统 HEIC 转码、iCloud、真实内存限制 |
| 鸿蒙及 HarmonyOS NEXT | 关闭 Worker、OffscreenCanvas、createImageBitmap 等增强能力，验证公共 Web API 回退 | 鸿蒙浏览器与 ArkWeb 实现、系统选择器、文件提供器、微信内核 |
| 相册停留/返回 | 暂停心跳并推进时间，检查同页续租；模拟其他页接管或清除 | 真机冻结、进程被系统杀死、系统事件顺序 |

同一页面的 9 秒租约过期本身不会拒绝保存，现有代码允许续租，不应简单延长租约掩盖问题。其他页面已经接管、版本改变或清除草稿时，旧页面仍必须停止写入。保存事务已经开始后不提供取消按钮，避免事务提交了却提示取消。

## 官方依据

- [PNG 规范](https://www.w3.org/TR/png/#11IHDR)允许交错方法 0、1；[eXIf 规范](https://www.w3.org/TR/png/#11eXIf)规定 TIFF 头和字节序。
- [MDN Blob.type](https://developer.mozilla.org/en-US/docs/Web/API/Blob/type)说明浏览器通常根据扩展名推断类型，不读取文件字节，不能单凭该属性判断内容。
- [Safari 17 的 HEIC 支持](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/)不能推广到旧版 Safari、所有 WebKit 构建或其他系统。
- [WebKit 267277](https://bugs.webkit.org/show_bug.cgi?id=267277)及[292350](https://bugs.webkit.org/show_bug.cgi?id=292350)记录了 accept 对 iOS HEIC 转码的影响；宽泛的 image/* 可能保留 HEIC，不保证转码。
- [Chrome 页面生命周期](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)说明隐藏页面可能被冻结，不能依赖心跳持续运行；这不证明所有系统选择器都会冻结网页。
- [MDN naturalWidth](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/naturalWidth)说明低端设备上的浏览器可能主动降低图片分辨率。自动化仅模拟这种尺寸变化，未验证具体手机的降采样行为。

## 真机补测

每个平台至少记录设备型号、系统及浏览器版本、是否应用内浏览器、构建版本和实际结果。只使用合成测试图片。

1. 系统相册、文件管理器分别选择 JPEG、PNG、WebP；同文件重试、取消选择、替换已有图片，核对预览与刷新后恢复。
2. iOS 使用 HEIC 原件和系统转成的 JPEG；Android/鸿蒙检查真实返回类型。无法解码时应就地提示在设备上转换为 JPEG/PNG，不能宣称所有 HEIC 均支持。
3. 相册停留 15 秒以上、切换应用再返回；同页可继续，有其他页接管时显示冲突且不覆盖。
4. 云端未下载的照片、受限文件权限、低存储空间、低内存和大像素图片，核对失败可恢复、旧图保留。
5. 最后一个槽位检查错误与取消按钮的可见性、系统字体放大、横竖屏、屏幕阅读器提示。

真机矩阵仍未验收。自动化不能证明系统选择器一定回传文件；若根本没有 change 事件，或进程被系统终止，网页无法依靠超时和错误提示恢复该次选择。
