# 纯前端浏览器兼容验收矩阵

状态：2026-10-14 纯前端已实现，自动化结果以VERIFICATION.md为准。下列系统及发行版浏览器仍需真机验收，名单不表示已经全部通过。

## 系统与浏览器

| 系统 | 系统自带浏览器 | 纳入验证的其他主流浏览器 | 重点场景 |
| --- | --- | --- | --- |
| HarmonyOS | 华为浏览器 | 设备上正式提供且仍维护的 QQ、UC 等发行版，记录实际版本 | 相册与文件选择、后台恢复、PDF 保存 |
| HarmonyOS NEXT | 华为原生系统浏览器 | 当时正式提供的原生主流浏览器，按实际发行版登记 | 独立真机验证，不套用 Android 结果 |
| Android | 三星 Internet、小米、OPPO、vivo 等厂商系统浏览器；华为 Android 设备按实际型号登记 | Chrome、Edge、Firefox、QQ 浏览器、UC 浏览器 | 厂商文件管理器、相册授权、低内存、返回操作 |
| iOS | Safari | Chrome、Edge、Firefox | 图片方向、下载或预览后存储到“文件”、后台终止 |
| iPadOS | Safari | Chrome、Edge、Firefox | 桌面网站模式、横竖屏、分屏、触控及硬件键盘 |
| Windows | Edge | Chrome、Firefox、360 安全／极速浏览器、QQ 浏览器 | 下载目录、缩放、键盘、国产浏览器内核模式 |
| macOS | Safari | Chrome、Edge、Firefox | 下载、中文字体、触控板、系统预览 |

默认维护厂商仍提供支持的系统，以及浏览器当前和前一稳定版本。随系统分发的浏览器按对应系统版本测试；OEM 和原生鸿蒙浏览器以实际可用发行版为准，不假定某个品牌在所有系统上都有版本。旧版支持范围需另行实测，不能仅凭品牌相同承诺支持。

不支持 IE、Edge 的 IE 模式及 360、QQ 等浏览器的 IE 内核兼容模式。国产双核浏览器使用其现代内核的极速模式。Chrome、Firefox 等在不同系统上的品牌名不代表相同实现，不能直接复用另一系统的结论。

微信、QQ 等应用内置网页单独记录，不能与独立 QQ 浏览器混为一项。若下载或存储受限，进入填写前提示使用系统浏览器；已经填写后不得直接跳转并声称草稿会同步，站点数据通常不能跨浏览器转移。

## 构建与能力检测

根目录 `vite.config.js` 的语法目标为Chrome/Edge 111、Firefox 128、Safari 16.4。Tailwind 4和实际Web API也有最低要求，因此这些配置值不是历史版本兼容认证。Playwright已配置Chromium、Firefox、WebKit三个项目，具体可运行情况、结果与限制见验证报告。

已联合核对 Vite、Vue、组件依赖和 Tailwind CSS 的要求，单纯降低 JavaScript 编译目标不能补齐缺失的 API 或 CSS。优先用能力检测选择实现，不靠 User-Agent 猜测功能，也不把所有鸿蒙版本归为同一种内核。

- 生产采用 HTTPS，检测可靠随机数、SHA-256、文件读取及 PDF 所需基础能力。关键能力缺失时，在录入敏感内容前给出明确提示，不静默取消图片判重。
- 保留不依赖主应用成功启动的基础提示，避免旧浏览器只出现白屏。能力不足时说明升级或切换浏览器的办法，不承诺所有历史版本均可用。
- 字体、转换代码和 PDF 依赖随站点提供；兼容回退不得改为上传图片或填写内容到外部转换服务。

## 功能回退和数据保护

| 功能 | 实现要求 |
| --- | --- |
| PDF 下载 | 生成完毕后由用户点击下载，基础路径使用 Blob URL 和下载链接；不以 `showSaveFilePicker` 为必需条件。提供用户点击的“打开 PDF”及系统保存指引，避免异步生成后自动弹窗被拦截。 |
| PDF 附件 | 下载完整文件与阅读器提取附件分别验收。系统阅读器不能提取附件时说明可用的附件阅读方式，不把附件缺失视为正常降级。 |
| 下载确认 | 下载事件、系统分享返回或页面重新激活均不代表已保存。始终由用户明确确认后清除；不在点击下载后立即撤销 Blob URL。 |
| 本地草稿 | 启动时执行实际 IndexedDB 写入、读取和删除探测，覆盖隐私模式、配额不足及升级阻塞。失败时不显示“已保存”。可由用户明确选择临时内存填写，并持续说明刷新或关闭可能丢失。 |
| 存储保留 | `navigator.storage.persist()` 和容量估计仅作增强，不能保证浏览器永不回收。按应用已完成的事务报告保存状态。 |
| 图片处理 | 支持浏览器内置解码器能处理的全部图片格式：JPEG、PNG、WebP 先按容器规范校验，GIF 按块结构校验，BMP、AVIF、TIFF、SVG、HEIC／HEIF 等经 `createImageBitmap` 或图片元素解码确认。优先使用可用的 Worker 图像 API，缺少 `OffscreenCanvas` 或 `createImageBitmap` 时回退至普通图片元素与 canvas 串行处理；保持相同质量和容量限制。超出 2500 万像素或最长边 8192 时自动等比缩小，不要求用户先处理。 |
| 文件选择 | 覆盖相册、拍摄和文件管理器，依据文件内容验证格式，不能只依赖 MIME 或扩展名。HEIC／HEIF 在 Safari 等内置解码器的浏览器可直接处理；Chrome、Firefox 等不能解码时给出明确的转换提示，不谎称已支持。 |
| Worker | 创建失败或能力缺失时可在主线程分批处理，显示进度并支持取消；不因此放宽输入硬上限。不可恢复的处理错误保留草稿、提供重试。 |
| 多标签页 | IndexedDB 事务版本、写入所有权和清除代次负责一致性。Web Locks、BroadcastChannel 仅作增强；缺失时使用轮询和页面激活检查。旧页面和延迟任务不能在清理后重建数据。 |
| 生命周期 | 在可用的页面可见性、pagehide、pageshow 等事件中检查状态；不把 beforeunload 当作移动端可靠的保存或清理机制。返回缓存、后台终止与恢复均需验证。 |

图片原件、压缩附件和最终 PDF 的限制沿用统一规则，不能给手机或某个系统悄悄降低内容完整性。不同设备实测无法承受既定限制时，应记录证据并调整统一安全限额或处理实现。

## 界面检查

- 继续覆盖 375／768／1024／1440px、臣服/午夜两套风格与日间/夜间模式；增加横竖屏、iPad 分屏、Android／鸿蒙折叠屏展开与收起。
- 检查安全区域、地址栏伸缩、软键盘遮挡、动态视口和表单焦点；固定操作栏不能遮住当前输入或错误信息。
- 保留页面缩放、系统字体放大、键盘导航和屏幕阅读器提示；触控操作不依赖悬停，图片槽位支持点击选择。
- 中文输入法组合输入期间不执行破坏内容的格式化；长文字、号码和错误提示可换行。

## 验收与证据

1. 对实际生产构建设置 Chromium、Firefox、WebKit 自动化项目，覆盖功能、安全、容量边界和回退分支，完成最终候选版本连续11轮回归。
2. 单独进行上述系统的真实浏览器验证。Playwright WebKit 不是发行版 Safari；移动视口或设备参数不是 Android、iOS、iPadOS 或鸿蒙真机。
3. 每个实际验证组合记录设备型号、系统版本、浏览器版本、内核模式、应用构建标识、测试日期、结果和问题证据。没有设备或未测试的组合明确标为“未实测”。
4. 完整流程包含年龄确认、全表必填、16张图片、压缩和判重、刷新恢复、长内容 PDF、中文分页、下载、附件字节校验、确认清理、重开及旧标签页检查。
5. 在受控测试中关闭增强 API，验证每条回退；覆盖配额不足、存储禁用、Worker 失败、下载取消、返回缓存及后台终止。测试使用虚构资料与合成图片。
6. 满容量图片和反复导出的终端资源压力，与静态站点并发访问分别统计。记录耗时、可观测内存及失败情况，不将旧后端100用户结果作为手机处理能力的证据。

没有实测证据的系统不得宣称“完全兼容”。尚未完成真机矩阵时，报告保留未验收项；不使用修改 User-Agent 或模拟窗口宽度替代验证。

## 本次本机观察

Chromium 156与Playwright WebKit 27.2已通过固定版本连续11轮回归，包含真实填写、16张图片、原附件摘要、PDF下载和清理；统计与限制见验证报告。WebKit隔离隐私上下文不能直接持久化Blob，已改用ArrayBuffer存储并在读取时恢复Blob，实际流程通过。高级图片API不可用时，JPEG/PNG/WebP均通过普通图片元素与canvas回退验证；本轮新增的自动缩小、EXIF 方向、GIF首帧与字体缺字替换规则已在本机Chromium和Playwright WebKit自动化中通过，其他系统浏览器与真机HEIC解码尚未验收。
